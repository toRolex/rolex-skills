# 工作现场

## 分派

启动、查询或获取结果时使用宿主现有接口，只在用到该动作时查看说明。若接口需要调用脚本，脚本只连接本批已确定的业务步骤，首批执行角色仍是 Implementer。工具调用和通知方式由宿主决定，角色分工以 [主流程](../SKILL.md) 为准。

真实能力不足时报告具体动作和影响范围。权限拒绝原样保留，不通过换工具、模型或代理绕过；不自行安装扩展或开发新的运行平台。

创建 worktree 前调用 Skill 工具加载 `wt-switch-create`；其他 Worktrunk 生命周期操作另一次加载 `worktrunk`。没有 Skill 工具时，按宿主支持的方式加载同一材料。Git 管提交与合并，Worktrunk 管现场生命周期，共享元数据操作串行。

1. 为每票建立独立 `afk/issue-{N}` 分支及 worktree，基于最近已验收的目标提交。记录绝对路径、分支和原始实现基线；已有同名现场先按 [重新开始规则](../REFERENCE.md#运行记录与重新开始)核对。
2. 给执行者 Ticket、目标分支、工作目录、基线、模型要求和对应模板。材料可直接传入或提供接收方能读取的地址，不假设不同环境共享相同路径。详细业务材料交给执行者按需读取。
3. 同时派本批 Implementer；同票的 Reviewer 接手前确认实现者及相关写入进程退出。Implementer 与 Reviewer 合计占用本批最多四个 Ticket 现场。

## 写入前与交接

每个角色先核对实际仓库根目录及分支，与分派现场精确一致后开工。文件操作用明确路径，Git 指明工作目录，测试在同次命令中进入指定目录；沿用已建 worktree，不再套一层隔离现场。

同一现场只有一个写者。辅助分析可只读返回建议，实际修改由当前角色执行。结束前处理自己产生的写入子进程，按 [失败与停止](../REFERENCE.md#失败与停止)核对退出；不接管用户或其他运行的会话。

角色结果包含 Ticket、阶段、实际目录/分支、成果 SHA、测试命令及结果、问题和退出情况。可以直接返回或保存到约定地址，格式不指定；关键结果须在交接、关闭或清理之前保存并可核对。只有业务完成消息时，不能推定所有写者已退出。
