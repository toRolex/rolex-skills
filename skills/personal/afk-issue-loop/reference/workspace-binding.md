# 现场绑定

## 控制者启动角色

直接使用当前宿主暴露的原生异步启动和最终通知；首次派发即真实 Implementer。操作发生时查看需要的接口，不枚举未来能力、不启动探测。不支持实际并行/现场指定/用户模型时，报告具体缺项，不偷偷串行代跑或改载体。

默认 subagent；显式 Herdr 时调用 Skill 工具加载 `herdr`，再使用当前接口，只管理本次创建的实例，保持权限和用户焦点。没有可用接口就阻塞，不安装扩展、不操作旧会话。

1. 新 Ticket 创建现场前调用 Skill 工具加载 `wt-switch-create`；需要 Worktrunk 生命周期操作时另一次调用 Skill 工具加载 `worktrunk`。用 Worktrunk 建独立 `afk/issue-{N}`，基于本批开始时最近验收目标提交，从返回值获得绝对路径。复用同名现场前读成果、原始基线及占用记录，不能覆盖 dirty 或活动任务；共享元数据动作串行。
2. 按 [薄记录](../REFERENCE.md#记录与再次调用)先保存 intent、运行/批次/Ticket/stage、模板、现场、基线、独占结果路径和模型偏好，再启动完整业务任务，补宿主 task ID。用户模型由真实启动选项/宿主配置表达，不用 prompt 冒充；已知实际模型与指定不符立即报告，不自动换模型。
3. Implementer/Reviewer 的 `EXPECTED_DIR=WORKTREE`、`EXPECTED_BRANCH=BRANCH`；Merger 为 `REPO`、`TARGET_BRANCH`。模板与证据都传绝对路径；不为复用现场添加新的启动隔离目录。
4. 结果关联后核对业务证据；交接前按 [有限停止与隔离](../REFERENCE.md#有限停止与隔离)核实退出。宿主覆盖写者的终态通知足够，不需要中途握手或 ACK。启动结果未知先核对，不能再派同现场写者。

**完成标准**：真实任务已启动且身份、现场可寻址；失败则记录具体原因及可能占用，不把启动失败当成未产生副作用。

## 角色绑定检查

业务写入前自行核对，成功即直接工作，不等待控制者确认。

```bash
git -C "$EXPECTED_DIR" rev-parse --show-toplevel
git -C "$EXPECTED_DIR" branch --show-current
```

规范化真实目录后与 EXPECTED_DIR 比较，branch 精确一致；同仓库/同 HEAD 不等于同现场。不符返回 `WORKTREE_MISMATCH` 并零业务写入。读取模板、目标仓库规范、CONTEXT.md（缺失读 CLAUDE.md 与相关 ADR）及指定成果材料。真实权限拒绝原样报告，不绕过。

文件工具始终使用绝对路径；Git 每次明确 `-C`；测试等命令在同一次调用中进入目标目录，不假设上次 cd 生效。只修改本 Ticket 或本批授权的目标现场，不写控制者 plan/dispatch。角色独占自身 RESULT_PATH，结果包含身份及关键证据。

同一现场唯一写者。需要辅助分析时子委派只读返回建议，修改/测试/commit 由当前角色执行；不能留下未登记的外部写入子进程。

**完成标准**：现场及材料匹配后直接执行模板；不匹配或权限失败返回事实，由控制者归类本次跳过/阻塞，而不是重派修复平台。
