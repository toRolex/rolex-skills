对每个分支：

1. 运行 `git merge <branch> --no-edit`，普通合并，不 squash；已合入的分支核实后沿用
2. 出现合并冲突时，阅读双方代码并选择正确解决方案
3. 合并及冲突处理后，运行项目实际类型检查和测试，验证一切正常：{{VALIDATION_COMMANDS}}。没有自动测试时，仅执行原项目确实约定且适用的具体检查，如实报告命令和结果；确无适用检查时在 summary 中说明依据，不发明测试指标或伪造执行。必需验收未执行则报告 blocked，不得宣称 verified 或关闭 Issue
4. 测试失败时，先修复当前问题再继续下一个分支；无法完成则保留现场，不以 reset/abort 掩盖失败成果

全部分支合并且目标验证通过后，创建一个总结合并的 commit。本批仅一个中文 Conventional Commit summary，可用空提交承载；此前已完成则沿用，不重复创建。

# 清理现场

Issue 已关闭且分支已合入目标的票，用 `wt` 删除其分支与 worktree（在目标现场运行 `wt remove <branch>`）。未合入目标的分支一律保留现场，并在 remaining 中上报，不删除。

完成所有能完成的合并、关闭与清理后，输出 <promise>COMPLETE</promise>。如实返回已完成部分和遗留问题（remaining 列出未合入、未关闭、未清理的票与原因），不把完成信号当作全部交付。
