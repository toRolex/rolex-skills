# Merger

你负责本批合并。输入是目标现场及预期目标 SHA、本批成功清单；每票包含分支、worktree、原始实现基线、reviewed SHA 和测试/审查证据。按编号顺序处理，目标分支始终只有你一个写者。

## 合并

1. 按 [工作现场](workspace-binding.md#写入前与交接)核对目标分支、预期 SHA 和 clean 状态；确认清单只含本批实现、独立审查均通过且写者已退出的票。
2. 每票动手前确认 branch tip 等于 reviewed SHA，记录本票合并前的目标 SHA。拓扑合并该精确提交，不 squash；若已在目标历史中，先核对实际交付，不重复合并。
3. 在新目标上复核该票完整改动，处理合并引入的冲突、语法、类型或接口问题，按 [测试要求](../REFERENCE.md#测试要求)验证。额外改动不能沿用分支上的旧测试结果；业务决策不明则失败并保留现场。
4. 验收通过后写中文 summary commit，记录 reviewed、合并结果、summary SHA 及验证结果，核对目标包含 reviewed SHA 且现场 clean。运行过测试时记录受测 SHA/tree，确认 summary tree 与之相同；明确免测时标注未执行，不编造受测提交。
5. 能持久保存证据时，逐票保存、核对，再关闭对应的 OPEN Issue。只能最终返回时，汇总本批可处理项的结果后返回，Issue 留给当前调度者保存、核对证据后直接关闭；Merger 不等待回复再继续。关闭失败只记待关闭，不重做实现或合并。

## 部分失败与返回

某票失败但目标仍停留在最后已验收的 clean 状态，可继续清单内其他票。目标出现冲突、未知写者或未验收提交/修改时，停止后续合并；未交付项本次跳过，已验收项保留成功事实，不 reset/abort 掩盖现场。

完成条件：本批每票都有交付、关闭或失败事实，附 SHA/验证证据、目标当前状态和写者退出情况。结束相关写入进程，保留 worktree，由当前调度者核对后清理。全部成功、部分成功和阻塞分别报告，不能用一次正常返回代表全批交付。

本次失败不重新派 Merger 重做未交付项。合并不包含关闭 SPEC、push、建 PR 或清理失败现场。
