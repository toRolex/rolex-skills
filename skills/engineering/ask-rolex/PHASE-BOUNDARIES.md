# 阶段边界

一个**阶段**是会话内的一块工作：访谈、实现、QA。这个定义故意模糊：当你想"好，这部分完成了"时，一个阶段就结束了。

**阶段边界**是两个阶段之间的间隙，也是这个决定唯一应该发生的地方。阶段中间没有决定要做：继续，或者把剩下的工作拆给 sub-agent。在阶段中间压缩会让 agent 失去线索。

## 五个选项

| 选项 | 作用 |
| ---- | --------------------------------------------------------------- |
| **继续** | 留在会话里。完全没有上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可移植的 markdown 文件，在任何地方用它开启新会话。 |
| **Sub-agent** | 把任务送到它自己的上下文窗口，拿回一份报告。 |
| **`/compact`** | 压缩当前上下文，用摘要开启新会话。 |

## 决策树

在边界处自上而下工作。第一个**是**胜出。

**1. 你能在这个会话中继续吗？** 两件事让答案是"是"：下一个阶段需要这个阶段作为**一手来源**，或者你有足够的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone) 剩余（约 150k tokens）让下一个阶段放得下。访谈 → 实现是标准的"是"：实现想要的是逐字的推理过程，而不是它的摘要。继续不花任何成本、不损失任何东西，所以先把它排除。

**2. 上下文与接下来要做的事无关吗？** 这个会话里的一切（探索、决策、死路）都可以丢弃吗？如果是，**`/clear`**。这是板上最便宜的招：不花时间，还回整个窗口。`/clear` 也不是终局：旧会话仍然可以恢复。

弄错的成本是单向的。清掉_相关_的上下文，你就失去了你构建的东西背后的**为什么**，无论怎么回读 diff 都要不回来。

**3. 你需要交接吗？** `/handoff` 很窄。你只在以下情况需要它：

- 换到**新 harness**（Claude → Codex），
- 移到**新目录**或仓库，
- 把工作交给**同事**，
- 或者在**阶段中间**发现一个旁支任务，需要分叉而不打断手头的事。

这个列表就是全部条款。`/handoff` 买到的是**可移植性**：一个能旅行的文件。如果没有东西在旅行，你就不需要它。

**4. 这个任务能 AFK 完成吗？** 它的范围是否足够窄，可以在你离开键盘、无需干预的情况下运行？如果是，把它交给 **sub-agent**，让当前会话不被触碰。自动 review 是标准案例：agent 读 diff 并报告，它做的时候不需要你。

**5. 否则，`/compact`。** 相关上下文、同一 harness、同一目录，而且你需要留在循环里：决策树落在这里，而且经常落在这里。给它一条指令（`/compact 我们要 QA 这个区域`），这样摘要保留下一个阶段需要的东西。

`/compact` 是**默认，不是首选**。它待在底部，因为上面四个问题都更便宜或更精确。人们从这里开始的失败模式是：新会话对摘要压平的一个决策自信地犯错。

## 一手来源和二手来源

除了**继续**之外的每个动作，都把**一手来源**变成**二手来源**：把如实发生的会话，替换成它的摘要。权衡的形状总是一样的：

| 来源 | 信息 | 噪声 | 可活动空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（继续） | 完整 | 很多 | 很小 |
| 二手（`/compact`、`/handoff`） | 有损 | 较少 | 很大 |

这就是为什么问题 1 排第一。只有当留下比省下更贵时，你才付出有损的代价。

## 这些都是判断

这些问题不是客观的：每一个都有主观成分，同一个边界在不同日子可能走向两个方向。价值在于**按顺序**问它们，在边界处而不是在工作中间问。
