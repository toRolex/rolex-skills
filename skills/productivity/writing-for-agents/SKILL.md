任何 agent 消费的文档的写作参考——一个 skill、一份 `AGENTS.md` / `CLAUDE.md`、一个被指针指向的文档。打包方式不同；写作方式相同：同样的杠杆让每一份都可预测——agent 每次运行采取相同的_过程_，而不是产出相同的输出。

当你写的文档是 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用选择和 router skills。

## 上下文指针

**上下文指针**是 agent 上下文中持有的一个引用，它指名一些上下文外的材料，并编码到达它的条件。skill 的 description 是一个；`AGENTS.md` 中命名一个文档的行是同一个对象。指针的_措辞_，而不是它的目标，决定 agent 何时到达材料——以及多可靠。一个必须命中的目标藏在措辞薄弱的指针后面，是一个方差 bug：先锐化措辞，只有锐化失败才内联材料。

指针做两件事——说明材料是什么，并列出来_应该触发到达它的**分支**（分支是文档处理的一个独特情况，所以不同运行走不同路径穿过它）。一个常驻指针的每个词在每个回合都花钱，所以它比正文更应受严格修剪：

- **前置首词**——指针是它做触发工作的位置。
- **每个分支一个触发器。** 把单个分支改名的同义词是一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已经携带的同一性。**

## 两种负载

你添加的每份文档和指针都花费两种预算之一：

- **上下文负载**——常驻材料在 agent 窗口上的成本：一行 `AGENTS.md`、一个 skill description、任何每个回合都在上下文里的东西，无论它是否触发都花 token 和注意力。
- **认知负载**——在人身上的成本：哪些文档存在、何时去够每一份。人是索引。不是要最小化的成本——它是人类主体性的价格；在人的判断重要的地方花它，在不需要的地方去掉它。

只有通过指针到达的材料，以指针自身那一行为代价逃出上下文负载；完全没有指针的材料完全骑在认知负载上。

## 信息层级

一份文档由两种内容类型构建——**步骤**（agent 执行的顺序动作）和**参考**（按需查阅的定义、规则、事实）——它们自由混合：全部步骤（一份配方）、全部参考（一次 review 的规则、本 skill）、或两者兼有。核心决定是每块内容在**信息层级**上的位置，一个按 agent 需要材料的迫切程度排序的阶梯：

1. **文件内步骤**——主层级：agent 按顺序做什么。
2. **文件内参考**——按需查阅。常常是一个合理平坦的同级集合（一次 review 的所有规则在同一级）——这是一个好的安排，不是坏味。
3. **披露参考**——被推出去放进单独文件，由上下文指针到达，只在指针触发时加载。范围从同一文件夹的兄弟文件，到完全外部、可以住在任何地方、任何文档都能指向的参考。

推得太少，顶层臃肿；推得太多，你把 agent 真正需要的材料藏起来了。那个张力就是整个决定。

**渐进披露**是沿阶梯向下移动的动作——离开主文件、退到指针后面——让顶层保持可读。主要不是 token 优化：它是保护层级的方式。分支是最干净的披露测试：内联每个分支都需要的东西，把只有某些分支达到的东西推到指针后面。当文档有步骤时，应该披露的文件内参考会埋葬它们，让注意它们变成掷硬币——一个方差杠杆，不只是可读性杠杆。

**共置**是文件内的同伴：阶梯决定一块内容_落多深_，共置决定它一旦落下_旁边坐着什么_。把一个概念的 definition、rules 和 caveats 放在一个标题下，而不是散落，这样读一个部分会带上它的邻居。测试：文档应该读起来像为 agent 写的文档——分组的内容那样读；散落的内容不会。（不同于重复：重复是在两个地方重复一个意思；散落是把一个意思碎片化到很多地方。）

**蔓延**是这里的失败模式：文档太长，即使每一行都活且唯一。注意力在多余内容上变薄，每一行额外内容都是要维持相关的更多内容。治愈是阶梯：把参考披露到指针后面，按分支或序列拆分，让每条路径只携带它需要的。

## 步骤和完成标准

每个步骤都以**完成标准**结束——告诉 agent 工作已完成的条件。两个属性让它成为杠杆：

- **清晰度**——agent 能分辨完成与未完成吗？一个模糊的边界（"理解了"）招来**过早完成**：在真正完成前结束步骤，注意力滑向_装作完成_。前方仍然可见的步骤——**完成后的步骤**——提供拉力；标准的清晰度是阻力。按顺序防御：**先锐化边界**（局部且便宜）；只有当它不可约地模糊_且_你观察到匆忙时，才通过拆分序列来隐藏后面的步骤——而且隐藏只在真实的上下文边界上起作用（一次交接或一次 sub-agent 分发；内联调用让后面的步骤留在上下文里，清不掉任何东西）。
- **需求度**——它要求多少。"每个被修改的模型都算到"强制彻底的工作，而"产出一份变更清单"不会。需求度驱动**苦功**——agent 在工作内部做的挖掘，潜伏在措辞里而不是写成自己的步骤——它不受步骤限制："每个规则都应用"绑定一块平坦的参考，正如"每个步骤都完成"绑定一个序列，这就是一份全参考文档仍携带穷尽性标准的方式。

最强的标准既可检查又穷尽。

## 何时拆分

把一份文档拆成两份花掉两种负载中的一种，所以只在拆分值得时才拆：

- **按序列**——拆一段步骤，其中完成后的步骤诱惑 agent 匆忙跳过眼前那个。让它们离开视野会在当前任务上驱动更多苦功。警惕反面：合并序列会把每个步骤后面的步骤暴露给接下来的，招来过早完成。
- **按调用**——skill 特有的：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是一个已经存在于模型预训练中的紧凑概念，agent 运行文档时用它思考（_lesson_、_fog of war_、_tracer bullets_）。作为一个 token 重复，而不是句子，它累积一个分布式的定义，并以最少的 token 锚定一大片行为，通过招募模型已持有的先验。自己造一个也行，只要你清楚定义它，但一个编造的词招募不到先验——你用定义 token 支付一个预训练词免费给的东西；先伸手拿一个现有词。

它双重锚定。在正文里，_执行_：agent 每次看到这个词都伸手拿同一行为，在平坦参考里它把注意力集中在一类要找的东西上。在指针里，_调用_：当同一个词住在你的提示、你的文档、你的代码库里，agent 把那个共享语言链接到材料上，更可靠地到达它。

寻找用引导词重构的机会。一个在三个地点展开的三元组、一个花一句话指向一个想法的指针——每一段都是乞求塌缩成单个 token 的段落：

- "fast、deterministic、low-overhead" → _tight_（一个 _tight_ 循环）。
- "一个你相信的循环" → _red_——一个模糊的门变成二元的可观察状态（循环在 bug 上变_red_，或者不）。

你赢两次：更少的 token，和给 agent 挂思考的一个更锐利的钩子。假设每份文档都携带引导词会退役的重述——去找它们。

**否定**是紧挨这个杠杆的失败模式：通过禁止来驾驶会把被禁行为拖进上下文，让它在场更多，而不是更少。_别想大象_，然后满脑子都是大象；否定是一个弱修饰符，强激活的概念会压过它，所以禁令有一半被读成"去做那件事"的指令。提示**正向**——陈述目标行为（"写一行注释"），这样被禁的那个永远不会被说出。禁令只有作为你不能正向表达的硬护栏才配有一席之地；即便如此，也把它和正向目标配对，让注意力落在要做什么上。

## 修剪

- 让每个意思保持**单一真相来源**：一个权威位置，这样改变行为是一次性编辑。**重复**——同一个意思在多个地方——花费维护和 token，并在阶梯上把意思的重要性抬高到它的真实等级之上。（引导词的一个意外反面：引导词是故意重复一个 token，绝不重复意思。）
- **环境**也是真相来源——`package.json` scripts、配置文件、目录布局、`--help` 输出——一份重述它的文档是一份**缓存**：一次查找的副本，只有查找昂贵时才挣得它的负载。缓存 agent 无法通过查找找到的东西：未写下的约定、选择背后的原因、没有配置坦白的坑。把单文件、单命令的查找留给环境，那里它们不会过时。
- 逐行检查**相关性**：它还关系到文档在做什么吗？一行因为从未关系到任务（纯粹说明，或一个应该被披露的分支）或因为随着它描述的行为或世界变化而过时，就失去相关性。更短的文档更容易保持相关。没有修剪纪律，默认命运是**沉积**：陈旧的层沉淀下来，因为添加感觉安全而删除感觉危险，直到你必须钻穿它们找到仍然活着的东西。
- 逐句寻找**无操作**：一个模型默认就会服从的指令，花负载什么都没说。测试——它改变行为相对于默认吗？——是模型相关的，不是读者相关的：两个对无操作意见不一的人是对默认意见不一，通过运行文档解决，而不是辩论。当一个句子失败时，删除整个句子，而不是从它里面修剪词。这个测试也给引导词打分：一个太弱、打不过默认的词（agent 已经相当彻底时还说_be thorough_）是一个无操作，修复是更强的词（_relentless_），而不是不同的技术。
