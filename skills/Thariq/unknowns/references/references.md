# References：用参考物表达意图

用户难以详细描述想要的行为或设计、缺少对应词汇，或复杂度让口头描述失真时，参考物比更多抽象追问更有效。本分支可在任意阶段触发，完成后返回触发它的阶段。

## 先向用户索取

先检查用户是否已经给过参考，已有的直接读取。尚未给过时询问：

> 有没有接近你想要的参考？可以是源码目录、library、设计组件、网站模块、文档、图表或图片。告诉我想借鉴哪部分；没有的话，你也可以让我找。

源码优先：它暴露行为、结构和约束，不只是截图。不同语言的实现也可以成为语义参考。用户只给图片或文档时先使用现有材料，不强求源码。

- **用户提供参考：** 读取指定材料，确认想借鉴的部分。
- **用户说“你找／你来定”或明确委托：** 派只读子代理搜索相关参考，任务中写明目标、现有约束、希望借鉴的行为与来源优先级。使用网页工具前遵守 browser-tools 路由；涉及库/API 用法时查询官方文档。子代理返回少量有证据的候选、源码指针、适用理由和局限。主 agent 复核，再让用户反应。
- **用户没有参考且未委托：** 询问是否由 agent 寻找或使用标注假设的样例；等待回答，不把“没有”当成搜索或选型授权。
- **搜索失败或来源不可访问：** 披露限制，保留 OPEN，询问替代材料，不编造源码或语义。

“你来定”可以授权推荐参考，但不自动授权改变产品合同、移植实现、发布内容或放弃后续反馈。

## 读懂再使用

产出简短的 semantics map：

| 来源与证据 | 要借鉴的行为／结构／风格 | 对目标任务的映射 | 不照搬的部分与差异 |
|---|---|---|---|

源码引用实际读过的文件和片段；截图只能支持可见表现，不能证明底层逻辑。明确哪些细节是用户想借鉴的，哪些只是原项目偶然实现。让用户确认理解，再用它喂给 brainstorm、prototype 或 grilling。

**完成：** 参考的来源、借鉴范围、迁移差异和用户确认记录已进入地图；找不到或未确认的材料仍标为 OPEN。之后返回原阶段，不开始生产实现。
