Implementation plan · 2026-09-12 · 待用户审阅

AFK：优先复用 Sandcastle 的修改计划

方向：以固定上游源码和三份角色模板为底稿，只做必要适配，不再重写一套概念相似的系统。

本轮只交计划。没有实施运行时、修改角色 prompt、操作业务 Issues 或提交代码。用户确认“沿用现有 Git 身份正常提交”是未来运行规则，不是本轮提交授权。置顶决策完成审阅后，才进入实施。
置顶决策流程与接口源码复用实施阶段验收机械同步

一、最值得先审阅的决策

“已确认”来自用户明确决定，不重新访谈；“待审建议”是尚未明确的实现边界，不冒充用户授权。每项以编号反馈即可。

D1 已确认取消四票上限，一次确定全部可执行 Tickets

决定：固定初始输入范围，每轮选择当前未被 blocked、且无权限或现场阻碍的全部开放 Tickets，并发运行各票 I→R 管线；等待本组 Promise.allSettled，中途不补位。关票和刷新后，再确定下一组。

理由：回到上游对计划中全部 issues 并发的形态，不再加入四票限制。原生 blocked_by 和固定 scope 仍保留，不恢复 LLM Planner。

影响：N 张可执行票意味着最多 N 个角色进程同时活跃，而非 2N；每票 I 完成后才接 R。资源及服务限流压力随 N 增加，不能偷偷加 semaphore 恢复四票上限。现场准备仍按原规则串行，不等于角色串行。优先级只确定稳定顺序，不再把低优先级就绪票截到下一批。

D2 已确认恢复完成信号与默认60秒 completion grace

决定：检测到上游 <promise>COMPLETE</promise> 前，使用600秒 stdout idle；检测后切换默认60秒 grace。后续每行真实 stdout 重置当前阶段的计时，包括解析器不识别的行；stderr、其他角色和监控消息不续期。正常退出不额外等待60秒，无角色固定总时长。

替代旧规则：此前“始终600秒、禁用completion grace”不再有效。持续输出可超过600秒；出现COMPLETE后静默60秒则允许进入执行收尾，不能再用旧“600秒前绝不收尾”的断言验收。

待审建议 D2a推荐保留业务交付门禁：grace到期触发受管执行收尾，确认进程结束后可以接受有效角色结果；没有有效成果、存在权限拒绝或终止不明时不能判业务成功。区分“调度器因grace发起的终止”和外部异常信号，不让正常grace一律因非零退出被判失败。理由：尽量保留上游完成语义，又不把打印信号误当合并、summary和关票已完成。

D3 已确认方向三份独立角色模板，使用上游中文版，仅微调

执行准则：以固定上游 implement-prompt.md、review-prompt.md、merge-prompt.md 逐段翻译为本地三份角色文件；保留章节、步骤顺序、具体检查列表及动态上下文位置。不是把当前改写版再次压缩。

  • 恢复 Implementer 最近十条提交、Reviewer diff/log 的启动前自动注入。
  • 保留 RGR、测试关注、未完成评论、不关票；Reviewer的 unsafe casts、any、嵌套三元等具体条目不能自行泛化删减。
  • 必要微调限定为：项目实际验证命令、提交规范、GitHub命令、目标现场、权限边界、AFK续作/close-only及结果输出。Reviewer“绝不改变行为”仅调整为保留预期行为、允许修复验收错误。
  • 移除 common-prompt.md 独立层，先把必要规则归入适用角色；不把整份common复制三遍，也不能只给Implementer保留公共边界。删除前核对三个角色条款完整性。
  • 调度状态、锁、快照等代码职责不扩写成角色流程；三份正文必须仍能与上游逐段对应。

待审建议 D3a结果接口先不大改：COMPLETE按上游恢复；脚本以短协议附加段提供仍必需的AFK结构化结果字段，不把复杂schema正文塞回三份角色职责。校验逻辑集中一处，不增加新层层封套。若需进一步删字段，先展示字段差异与消费者依据，不静默改变公共接口。

D4 已确认确定性分支复用；dirty保留，clean可清理

决定：沿用 afk/issue-N 确定性命名，已有属于该票的worktree与提交继续使用。整条I→R管线结束、写者终止确认后执行close：dirty目录保留；clean目录可由Worktrunk删除，保留branch和commits，失败重选可从保留分支重建。

边界：I→R交接中间不删除目录；目标Merger现场、归属不明或有未确认写者的目录不自动清理。清理异常不得掩盖已经获得的交付结果。仍使用既有明确归属确认，确定性名称本身不是接管其他任务的许可。

推荐：将安全且归属明确的clean任务目录纳入正常close，而非继续一律保留；不用原生git删除绕过Worktrunk，也不自动批准其hooks。

D5 已确认沿用现有Git身份正常提交

决定：使用现有仓库/用户Git配置及原有授权环境生成正常commit，不自动写 git config --global 的姓名、邮箱或safe.directory，也不换身份。缺少身份或出现目录信任问题时报告用户处理，不改成本地配置偷偷绕过。

保留：角色按任务实现、审查、合并及summary需要提交；没有新增自动push、PR、fetch/pull或同步origin。源码提取时必须排除上游宿主全局写配置和权限bypass路径。

D6 待审建议全部内部依赖阻塞时，保留单候选fallback例外

推荐：正常情况只并发未blocked票；没有正常候选且仅被范围内开放依赖阻挡时，沿用此前单候选fallback：直接开放内部依赖数量最少→优先级→编号。明确标为例外，不把仍blocked票伪称“就绪”。

理由：旧规格和上游Planner均有全内部阻塞的单候选策略，本轮未明确撤销。权限拒绝、状态unknown、范围外开放前置、现场阻碍不得进入fallback；保护尚待Merger交付的前置，不能借fallback重做已进入交付阶段的票。

可否决项：如果“只有未blocked才能执行”要成为无例外规则，就删除fallback，全部阻塞时报告等待原因。本计划不预先把任一选择当作已确认。

D7 待审建议优先源码级提取与随包分发，不再为零依赖重写

推荐：先列必要源码、依赖闭包、许可证和构建产物；可直接提取的保留函数/分支结构，环境差异放在薄适配层。若保留必要依赖更能避免重写，优先评估将其合法随skill打包，而不是以“零npm”为硬约束重写框架。

不可越过：不依赖Sandcastle原包，不在运行时下载/安装，不依赖开发期临时checkout，不擅自装工具或改变权限。具体依赖清单、体积与产物可追溯性在P0列出；需要新增构建/分发依赖时先呈现方案，未确定前不宣称“复制完整Effect模块即可零依赖”。

D8 待审建议简化证明机制，保留最小交付状态

推荐：删除目标HEAD＋binary diff＋文件stat严格相等的交接协议，以及summary标题历史计数证明；保留普通现场、分支成果和GitHub状态核实。保留驻内存的实现/审查/合并/仅待关闭阶段，不建立持久化恢复账本。

失败语义：临时准备错误后批可重选；关票局部故障不挡其他可关闭票；结果封套坏了但可能已有summary/关闭副作用时，先核实已有事实，不能直接重跑或假报成功。无法确定才报告具体用户待办，不以新证明平台填补所有不确定性。

免测建议：默认仍要求实际项目验证；仅用户明确免测时，结构化记录授权范围及not-run，修复“文档允许、代码无限重试”的矛盾。无自动测试但做了人工检查，不等于免测。此项接口需审阅，不默认为所有任务放宽验证。

四、实施顺序与完成条件

P0 · 冻结本轮决定与依赖闭包

复查工作区，保护既有无关修改。将最新决定与旧Issue/ADR冲突逐条标出；列出可直接提取、薄适配、AFK新增、非目标裁剪。呈现依赖/许可证/产物方案后才选分发方式。

完成条件：置顶待审项有明确反馈；必要闭包可解释；无“为了零依赖再重写”的暗中决策。没有取得的技术结论标待验证。

P1 · 三角色模板与上下文接线

逐段翻译上游三MD，接入真实模板处理，恢复Git log/diff预注入。父SPEC按原生关系/正文链接/显式输入提供并按票关联；显式全局上下文与父关系区分，不能擅自猜关联。刷新失败仅影响依赖该上下文的票。核对必要边界后移除common。

覆盖：F05、F15、F22。完成条件：三份上游/中文对照只剩可说明的微调；实际CLI stdin包含对应Git证据；参数中的命令不执行；安装路径独立、坏模板/展开失败可见。

P2 · Provider、终态结果与错误分类

提取事件解析及终态槽、boundedTail和结构化提取。错误区分明确拒绝、终态失败、可恢复事件、用户停止、诊断；保留原始输出，避免旧passed兜底与测试文本误分类。集中结果校验，保留可核实部分成果及错误原因。

覆盖：F06–F09。完成条件：旧passed＋新无封套、坏JSON后终态、EPERM测试文本、plain拒绝、aborted不同来源都有预期结果；诊断不成为业务成果。

P3 · 真实本机生命周期与双阶段计时

以no-sandbox/Orchestrator为底稿接本机监管。恢复idle/grace，区分grace主动收尾与异常死亡；修启动有界、控制命令引用、日志故障不阻stop、异常清理/终态日志。核对父exit后活跃后代、脱组持管道边界。

覆盖：F10–F14、F23。完成条件：公开stop不再派角色；所有声称受管的写者终止确认后才交接；无法证明的能力收窄并报告，不以kill请求或Promise取消冒充结束。若真实CLI进程行为要求额外机制，先呈现证据与最小方案，不另建守护平台。

P4 · 批次选择、成果复用与close

去四票截断，全体可执行票固定定批；保留串行准备与并发I→R。准备临时失败释放自身锁并允许下轮考虑，重试前复核实际branch；不把通用ENOENT永久归为用户阻碍。确定性分支、dirty保留、clean安全删除和重建分开实现。

覆盖：F01、F20、F21。完成条件：五张就绪票同批并发；中途解除依赖的第六票不补位；dirty/历史commit复用，clean删除后分支仍可合并/重建；fallback遵循审阅结论。

P5 · 单Merger、交付续作与最小门禁

close-only逐票故障隔离；删除额外快照/标题计数证明但保留实际成果检查。目标未完成由Merger接续；summary后坏封套先核实，已完成不盲重做；防误关票掩盖失败。明确免测授权与not-run表示。

覆盖：F02–F04、F17–F19。完成条件：某票unknown不挡其他可关闭票；批末一个summary且之后关票；partial merge/close-only/坏封套路径不假报交付，不新增持久恢复账本。

P6 · 文档一致性、安装态与全量验收

同步现行文档，按本轮新决定重新验收；审计报告保留为当时快照，不改写旧失败记录。逐项核对F01–F23和源码提取差异。

覆盖：F16及全部回归。完成条件：提供公开入口、三CLI、真实时间、安装态四类证据及未通过/未测项目；无旧四票上限、禁止grace、common注入或一律保留clean的现行规则残留。

五、验收清单

以公开 start/status/stop 为主验收接口。临时Git仓库、受控CLI/GitHub fixture用于失败和时序；不新增专门runner test脚本到仓库。纯函数与上游测试用于补充，不能替代公开入口。
