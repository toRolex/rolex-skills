① 待你拍板的决策（按你调整概率排序）

D1失败策略：0 自动重试，失败即落盘交人 已确认

agent 失败（抛错 / watchdog 判死 / 空产出）→ 标 failed、写恢复手册、不停调度其余 unblocked issue，收尾把 docs/afk-failures/ 清单交给你逐条处置。不再有「原地重试」。

理由：严格对齐 sandcastle——它对 agent 失败就是 fail-fast 零重试（maxRetries=2 只管 structured output 校验，不管 agent 失败）；AFK 时自动重试救不了能力不够的 issue，瞬时故障由恢复手册覆盖；且符合你定的「sandcastle 没有就不要」原则。

备选 b：保 1-2 次自动重试（attempts<2 时自动走恢复路径 A），偏离 sandcastle 但抗网络抖动 / rate limit。

D2恢复机制：单路径「重跑 + 复用现场」+ 恢复手册 已确认（B，经源码修正）

只保留一条恢复路径——对齐 sandcastle 对一般 agent 失败的真实实践（dogfood：失败后外层循环重跑，确定性 branch 名复用 worktree 捡回 commits，ADR 0003）：

sandcastle本 skill 同效物
重跑同 branch + worktree 复用（ADR 0003）恢复 = 同分支同 worktree 重新分派，prompt 附「Read 恢复手册了解前次失败」——进度从 git 历史自动捡回
确定性 branch 名 sandcastle/issue-{id}（重跑落回同一 worktree 的前提）已有：afk/issue-{N}
复用红线：clean→ff / dirty→带警告复用 / 永不 reset --hard已有红线强化成文：失败不清 worktree、不 reset、未提交改动保留
preservedWorktreePath + RecoveryMessagedocs/afk-failures/issue-{N}.md 恢复手册（格式见下）
# docs/afk-failures/issue-{N}.md
branch:   afk/issue-{N}          # 确定性分支，重派落回同一 worktree
worktree: <绝对路径>

error:    AgentIdleTimeoutError  # 借 sandcastle 错误词汇

## 恢复（= 重跑同 branch + worktree 复用）
重新分派，prompt 末尾附：
Read docs/afk-failures/issue-{N}.md 了解前次失败，同分支继续，复用已 commit 进度。

为什么不是 resume（源码修正，推翻此前"A 更接近原版"的说法）：sandcastle 的 resume() 全仓库仅两个真实用例——structured output 校验重试（#825）和 produce→extract 两段式；失败恢复零用例。它对一般 agent 失败的官方姿势就是"不续 session，靠确定性分支名重跑捡回现场"。且重跑式跨会话天然有效（compact/新会话后照样用），无 agentId 同会话限制——AFK 场景的关键属性。

D3超时协议：watchdog 取代复杂度分级 已确认

每次分派挂一个后台 watchdog 脚本（run_in_background）：盯 worktree 文件 mtime + git reflog，600s 无活性才退出（退出即系统通知唤醒控制者）→ TaskStop agent、按 AgentIdleTimeoutError 走失败流程。运行期间零输出、零上下文占用。agent 正常完成时控制者收系统通知后杀掉 watchdog。

理由：判据从「超了 X 分钟」（wall-clock 拍脑袋，误杀长测试）变成「600s 无任何进展」（对齐 sandcastle 的 idle 语义）；阈值 600s 直接抄 DEFAULT_IDLE_TIMEOUT_SECONDS。删掉 2-20 分钟复杂度分级表。subagent / herdr 两载体统一（盯文件系统，不盯 agent 类型），轮询全删。

职责边界：watchdog 只防一种情况——挂死。agent 正常结束或报错由系统完成通知接管，watchdog 不介入（控制者收通知后杀 watchdog）。

显式排除 completion grace（sandcastle ADR 0019 的 60s 宽限）：它的场景是「signal 已发出但进程挂起不退」；你的完成终点是系统通知（进程已退），不存在这个中间态，故不移植。

已知差距：信号源是文件活性而非 stdout 行流（Agent 工具不暴露流）——agent 长时间纯思考不落盘会误判，600s 阈值下实际概率低。

D4herdr 简化 + 轮询全删 已确认

保留 [mode=subagent|herdr] 参数。SKILL.md 的 herdr 段压缩为：「用 /herdr 开新窗口跑同一套角色 prompt；herdr CLI 操作与报错细节见 herdr skill」。删 reference/herdr-notes.md 整个文件（轮询协议随之消失），REFERENCE.md / EXAMPLES.md 里所有轮询表述删除。

D5脚本边界：只做 3 个 已确认

「sandcastle 没有就不要」筛后剩 3 个，scripts/ 下 bash+jq：

脚本契约sandcastle 原型
validate-plan.sh <plan.json>schema 校验 + branch 名格式 + blocked_by 引用存在 + 无环检测；exit 0/1 + 错误行Output.object + zod
watchdog.sh <worktree> [600]静默循环，idle 超时才退出（exit 1 + 一行死因）Orchestrator idle timeout

砍掉的 4 个：拓扑切片、status 状态机、收尾验证、分派锁——sandcastle 无对应物，控制者继续 LLM 推理 + 手动 Edit。

D6afk-plan.json schema：变更 撤销，一个字段都不加 已确认

D2 改为重跑式恢复后，agent_id 失去存在理由（恢复不依赖它，watchdog 的 TaskStop 目标是分派时会话内持有的 task 引用，无需落盘）；worktree 路径由确定性 branch 名可推导。0 自动重试后 attempts 也不需要。

{"number", "title", "branch", "blocked_by": [...],
 "status": "pending|dispatched|done|failed"}   # 维持现状，自造词汇（sandcastle 无对应）

符合「sandcastle 没有就不要」——它的 plan 也不持久化任何恢复辅助字段，恢复信息全在 branch 名与 worktree 里。
